# 数据定义

- `scans.csv` 每行一个收件。`event` 和 `tag` 是保形字符串，`flight` 为机场航班号，`leg_hint` 为可空精确航段。`action` 取 `SORT`、`LOAD`、`OFFLOAD`。`effective` 与 `received` 为带偏移 ISO 8601，后者不能早于前者。UTC 精度微秒。原因码同 `app/reasons.py`。
- `legs.csv` 含唯一 `leg`、`flight`、`start`、`end`、`destination`。窗口 `[start,end)`，用 UTC 比较。存在明确提示时仍须命中时间和航班。无提示且有多候选时隔离。`manifest.csv` 每个 `tag` 只出现一次且 `planned` 必须引用已知 `leg`。
- 原件只接受 UTF-8，可带 BOM。物理起始行号保留。重复表头计分段，空行单计，宽度不符保留整行。空文件、全空记录、仅表头分别有明确失败。`-`、`N/A`、`NULL`、`未知` 与空串都不参与必填匹配。API 中被归一化的可选提示用 `null` 表示缺提示。
- 同扫描编号按航段提示、航班、动作、行李牌和生效时刻比较。内容相同取最早收件，内容矛盾整组隔离。不同编号同牌同航段同刻同动作只改变一次状态。收件决定迟到标记，生效决定回放。同刻相反装撤产生冲突，后续有效动作可确认新末态。
- 计划段装载且无未决装撤及错装时计已装。计划段末态撤下计明确未装。其他计划件待证。错载按非计划段末态装载记录，按牌去重计件。清单外行李另外列出。列宽失配行只提供原始字段，不对其牌号做确定归属。
- 校时记录（可选第四份 CSV，建议名 `clock.csv`，也接受 `corrections.csv` 等常见名或请求体 `clock`/`corrections`）按 `event`（或 `tag`）指向扫件，给出确定修正时刻（`corrected`/`standard_time` 等绝对时刻）或偏差区间（`offset` 单值、`offset_min`/`offset_max`、`offset`±`uncertainty`，单位可在表头用 `sec/min/hour` 标注，缺省按分钟）。修正一律从扫描原始生效时刻 `effective_original` 起算，重复提交同份记录（同号或同内容去重、归档内容散列）不会叠加。偏差区间 `[effective_lo, effective_hi]` 与航段半开窗口相交出两个及以上候选段时记 `CLOCK_SPAN`/`LEG_AMBIGUOUS`，该牌先列待证；同批其余记录照常关联入账。确定修正使扫件改属另一航段时，后续关联与回放都在新航段重算，原航段不再包含该动作；装撤生效先后因此颠倒时按生效时刻回放改判末态。
- 批次由规则版本与三份文件内容哈希决定。SQLite 一次提交原件和结果；同源并发使用唯一键，复算比较结果散列。证据签发核对两个摘要及守恒，归档原样含 UTF-8 BOM。
